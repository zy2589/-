# GitHub 发布规则

- 仓库保持公开，不调整可见性。
- 只有用户明确说“上传”后，才创建或上传新的 GitHub Release/版本标签；构建、安装或修复本身不触发上传。
- 每次发布使用本地日期和时间命名，按用户既定要求同时准备独立可用的安装包与便携压缩包；压缩包及校验文件作为 Release 附件。
- 每个 Release 的版本说明都附安全审核报告。报告按项目实际风险填写，缺少证据的项目标为未验证/不适用，不编造检查结果。
- 安全审核报告整体放在 GitHub Markdown `<details>` 折叠区中，摘要写“安全审核报告（点击展开）”；需要表格表达的检查项用表格呈现。不包含数字签名状态。
- 发布说明模板见 `GitHub发布说明模板.md`。本地完成构建、复检和报告后，等待用户明确授权上传。
