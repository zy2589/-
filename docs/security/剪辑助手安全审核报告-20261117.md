## 发现与修复

| 严重度 | 发现 | 处理 |
|---|---|---|
| 高 | 导入工程中的 `spliceRegions[].borderColor` 被直接插入 SVG `stroke` 属性。构造特殊颜色值可形成属性注入；旧策略允许内联事件脚本执行，进而触达本机 RPC。 | 新增仅接受 `#RGB`/`#RRGGBB` 的 `sanitizeSvgPaint`，无效值回退到默认色；画中画预览改用该函数，并覆盖恶意属性、URL 绘制值的回归用例。 |
| 高 | 两个没有 UI 调用点的通用 RPC 暴露了不必要的本机能力：`registerAsset(filePath)` 可把任意非凭证本机路径注册为 WebView 资源；`saveProject(data.projectPath)` 可按传入路径写文件。 | 从 `nativeMethods` 中移除这两个 RPC 和对应通用写文件函数。工程自动保存仍使用固定工程存储路径的 `saveProjectSnapshot`。 |
| 高 | 响应 CSP 使用 `script-src 'unsafe-inline'`，会放大任何 HTML/属性注入的影响；两个缩略图模板也使用内联 `onerror`。 | 每个 HTTP 响应生成 192 位随机脚本 nonce；所有页面 `<script>` 标签加 nonce；设置 `script-src-attr 'none'`，脚本策略不再含 `unsafe-inline`，仅保留 WebAssembly 所需的 `wasm-unsafe-eval`。两个缩略图错误处理改成委托式事件监听；UI 构建门禁拒绝重新引入常见内联事件属性。 |
| 中 | Windows 凭证迁移时若 DPAPI 保护失败，旧逻辑会继续返回磁盘上的明文凭证。 | 现在保留原文件但拒绝加载明文，并返回明确的安全错误；DPAPI 可用后用户仍可迁移/重新保存。原有 `DPAPI1` 凭证继续按旧熵值解密再迁移。 |

## 已验证的保护

- 本机编辑服务只监听 `127.0.0.1`；检查 Host、Origin、随机会话令牌，并使用时序安全比较。
- RPC 请求校验 `Content-Length` 与 `Transfer-Encoding`，拒绝冲突分帧；RPC 正文与上传均有大小上限。
- 素材注册会拒绝凭证目录；字幕 PNG 写入限定到已登记目录、限定文件名和 PNG 签名。
- WebView 外部导航受宿主限制；新窗口只允许用户发起的 HTTP/HTTPS 链接交由系统浏览器打开。
- 用户/本机凭证种子及本地缓存由构建流程排除。当前树与 Git 历史的常见 Google API/OAuth、GitHub token、AWS key 和私钥格式定向扫描没有命中。定向规则不等同于可证明仓库不存在任何秘密。

## 剩余风险与限制

1. 通用 `yt-dlp` 下载入口会处理用户提供的 URL；TikTok、Google Drive 等特定下载路径有更严格的地址处理，但并非所有通用 extractor 都统一限制为公网地址。不要打开不可信来源提供的下载链接；本轮未做 SSRF/重定向/代理的在线渗透测试。
2. 工程归档导入有路径遍历与链接类型检查，但没有针对所有格式统一设置解压后总大小/条目数上限。打开不可信的大型工程档案仍可能造成磁盘或 CPU 消耗。
3. 没有使用恶意媒体、畸形 `.zpe` 档案、真实第三方下载站或 AI 账户执行端到端攻击测试。
4. 本轮没有重复验证字幕编辑、复杂多轨、画中画导出、外部服务、下载/降噪等完整产品工作流；该范围按 `docs/打包前复检清单.md` 保持未验证。
5. 报告中的密钥扫描是定向格式扫描，不能覆盖所有自定义令牌格式；依赖审计反映扫描时数据库中已知漏洞，不代表未来版本状态。
