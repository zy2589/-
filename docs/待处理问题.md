## [P0｜最高优先级] 删除重复文案误删整组字幕

- **记录日期：** 2026-11-16
- **现象：** 用户再次反馈删除文案时仍会把全部文案删除；上一轮标记“待实际复核”后，仍未把对应删除入口纳入真实回归。
- **根因：** 批量删除对应紫色字幕时，只要一个词匹配提示，就会删除整个字幕对象；同一 issue ID 被不同时间段复用时，还会跨时间段清除提示。整句分组字幕因此可能连同未选中的词一起消失。
- **修复：** 已改为按 issue ID、时间段、字幕轨和所属素材逐词删除；同一字幕组内的其他词、相同 issue ID 的其他时间段和其他轨道都要保留。缺少逐词时间信息而无法安全局部删除时取消操作；删除会清空全部文案时也取消。
- **回归要求：** 每次打包必须通过 UI 构建器中的隔离回归，并在实际工程副本中删除一处重复文案，检查同一字幕组剩余词、重复区间前后内容、复用 issue ID 的其他时间段及其他轨道；保存、重开后再次确认。未完成人工复核不得称为已解决。
- **状态：** 最高优先级；源码修复、批量删除入口隔离回归和全量构建门禁通过，安装版已更新。真实工程 UI 保存/重开复核尚未完成，未标记为最终验收通过。

## 分区预览与时间线轨道顺序错配（源码已修，待实际复检）

- **记录日期：** 2026-11-15
- **现象：** 上下等分布局播放时，预览中的分区/叠放位置与时间线视频轨道不一致。
- **根因：** 普通预览叠放使用真实 `trackOrder`，但自动分区逻辑把主视频硬编码为第一个分区，视频轨素材再按另一份只含叠加素材的列表偏移一格；主视频映射到较低轨时，预览分区仍会错误地把它放到上方。播放预览缓存键也没有记录轨道顺序和分区参数，快速播放路径可能沿用旧场景。
- **修改：** 主视频和叠加视频现在按同一份实际视频轨道顺序分配分区；预览场景缓存键加入轨道顺序、布局类型、比例、斜切角度及分区几何，布局/换轨后重建正确合成。导出复用相同的分区解析函数。
- **验证状态：** 源码已检查；当前最近工程没有分区素材，尚未对实际分区工程播放与导出验收。打包前按 `打包前复检清单.md` 完成上下、三分区、四分区、斜切、画中画以及换轨播放检查。

## 主窗口区域切换重复刷新（本轮再次定位并修复）

- **记录日期：** 2026-11-15
- **现象：** 软件启动时有明显刷新；下载、剪辑、抠图区域切换时仍闪烁，尤其是下载与抠图来回切换。
- **期望：** 三个区域留在同一个主窗口，切换不黑屏、不闪白、不重建页面，并保留页面状态。
- **结构核查：** 下载区与抠图区由同一个 Tk 根窗口承载；抠图 `RotoscopeWindow` 使用传入的 Tk `host`，正常嵌入时不新建顶层窗。剪辑区由同进程 WinForms/WebView2 子 HWND 承载，另有本地 Node 服务；它不是第二个顶层应用窗口，但渲染窗口类型与 Tk 页面不同。
- **上一版定位有误：** 上一轮只看 180ms 后的页面快照，因此把切页重绘误判为已消除。用户反馈仍闪后，重新查看本机最新日志 `ui-page-20261115-152620.log`，发现每次点击后旧页先 `Unmap`，目标页在 idle 快照中仍是 `mapped=0,size=1x1`；约一轮 Tk/Windows 几何处理后才变为 `mapped=1,size=1436x962`。因此切换过程确实先露空，再完整绘制一次。
- **剪辑页第二次闪现：** 同一日志和 `desktop-20261115-152953.log` 显示，剪辑页先切出空宿主，随后才创建 WebView2；首次导航与页面就绪晚约 2 秒。用户看到的是页面容器先出现、WebView 内容随后出现，并非两次导航。旧探针只断言 180ms 后页面状态，漏掉了 idle 阶段的 1×1/未映射状态。
- **本轮结构修改：** 三个主页面以及抠图的两个页面实例在窗口初始化时一次映射，后续只用 `tkraise()` 改变层级，不再切换 `grid()`/`grid_remove()`。剪辑页首次打开时，在当前页面后方预热 WebView2；收到 `IsReady` 后才切到剪辑页，加载期间不把空宿主呈现给用户。下载器、剪辑器和抠图器的实例均保留。
- **验证：** 更新后的实际 GUI 探针逐页记录 idle 与 180ms 快照，三页切换时所有主页面始终 `mapped=1` 且尺寸保持 1020×700；抠图子页始终映射且尺寸保持 996×635；点击剪辑时保持原页面直至 WebView2 已就绪。剪辑只出现一次初始 `NAVIGATION_START`，无切页导航；各次切换的 idle 日志无主页面 `Map/Unmap` 事件。
- **录屏与旧日志：** `屏幕录制 2026-11-15 102550.mp4` 约 30 fps 抽帧检查，区域转换发生在相邻帧内，未采到整屏黑/白帧；这无法排除小于一帧的短闪。旧版桌面日志每次只见一次 WebView 初始化/就绪，没有 renderer 崩溃或恢复记录，但当时没有页面切换和导航计数，因此不足以定位短闪。
- **诊断：** 每次区域切换记录页面映射、尺寸、Tk 句柄和 `Map/Unmap/Configure/Expose` 事件；记录抠图控件构建/导入耗时。剪辑宿主记录 WebView 导航开始/完成。不记录导航 URL 或会话令牌。日志位于 `用户数据/运行配置/logs/ui-page-*.log` 与 `desktop-*.log`。
- **后续反馈与日志边界（2026-11-15）：** 用户再次反馈启动及三页往返仍有明显刷新感。最新桌面日志只记录一次启动 WebView 导航、切页没有第二次导航；页面日志切页时没有卸载事件，但这些日志不包含每帧合成/窗口曝光的完整时序，不能推翻用户观察，也不能证明短闪已消除。
- **验证状态：** 结构探针证明页面保持映射且无切页导航；用户可见的刷新感仍未通过验收。下次打包前必须冷启动并录屏来回切换下载、剪辑、抠图，检查是否二次绘制/黑屏/闪白；失败时继续查 Tk/子窗口暴露与 WebView 首帧，不得把本项标为已解决。
- **参考原理：** [Tkinter 事件循环与 `after`](https://docs.python.org/3/library/tkinter.html)、[WebView2 线程模型](https://learn.microsoft.com/microsoft-edge/webview2/concepts/threading-model)、[Windows 同级窗口与 Z 顺序](https://learn.microsoft.com/windows/win32/winmsg/window-features)、[`SetWindowPos` 重绘行为](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowpos)。
