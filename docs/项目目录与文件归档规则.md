# 项目目录与文件归档规则

## 固定目录

| 路径 | 用途 | 归档规则 |
| --- | --- | --- |
| `core/` | 应用、下载器和编辑器源码 | 只放代码及代码所需的内置源码；不要存放导出成品或工程数据 |
| `assets/` | 界面和随包静态资源 | 只放应用运行所需资源 |
| `resources/` | 媒体引擎、模型和运行时资源 | 只放随应用发布的运行资源 |
| `用户数据/` | 工程、运行配置、日志、下载设置 | 用户数据长期保存，不清理、不混入源码 |
| `.venv/` | 开发与构建 Python 环境 | 启动/安装依赖的开发环境，除非重建环境，不移动 |
| `.build/` | 构建临时目录 | 只存放可重新生成的构建中间件，由构建脚本管理 |
| `release/` | 构建发布目录 | 只存放可安装程序包；可以保留作本机安装或备份，不纳入源码提交 |
| `docs/` | 操作说明、修改记录、参考图片 | 新增的维护文档统一放这里 |

## 根目录约定

根目录保留 `README.md`、依赖清单、主程序入口和安装/运行/构建脚本。新建说明文档或截图归入 `docs/`；不要再把临时说明散放在根目录。

## 运行期间生成的文件

- 工程、设置和日志使用 `用户数据/` 中应用已配置的子目录。
- 下载和导出结果写到用户在软件中选择的目录，不擅自改写目标位置。
- 下载、降噪和抠图的临时文件使用程序专用的临时目录/文件前缀，并在处理结束后清理；不要把临时结果当作发布资源。
- Python 缓存不写入源码树。`.gitignore` 忽略 `__pycache__/` 与 `*.pyc`。
- 构建生成物进入 `.build/` 和 `release/`；不要放进源码、静态资源或用户数据目录。

移动或清理目录前，先检查启动脚本、构建脚本和代码是否使用了固定路径。`core/`、`assets/`、`resources/`、`.venv/`、`用户数据/` 以及 `release/` 都有明确用途，不作为普通临时文件夹清理。
